# Frontend Component Registry

Purpose: quick discovery of reusable UI blocks under `FRONTENT/src/components/`.

Rule: update this file whenever a new reusable component is added or a listed component's API changes.

Design principle:
- Prefer tiny, single-responsibility reusable components.
- Avoid page-private one-off wrappers unless there is a clear reuse path.
- **Dashboard and metric presentation lives in `_dashboard_widgets/`** — pure, stateless, resource-unaware widgets with no injects, stores or closures. The matching `sections/*.vue` is a thin adapter: it injects the page contexts, resolves closures via `evaluateProp`, applies section chrome and the hide rule, then mounts the widget. See [_dashboard_widgets/REGISTRY.md](./_dashboard_widgets/REGISTRY.md).
- **Every prop a caller might replace with their own markup must route through `abstract/Renderable.js`** — see [UI_RENDERABLE_CONTRACT.md](file:///f:/LITTLE%20LEAP/AQL/Documents/UI_RENDERABLE_CONTRACT.md). A prop interpolated straight into a template is closed to `_ui/` customization and forces tenants into a full `.vue` override.

## Base Field System (`src/_fields/`)

One folder per field type, each holding three explicit SFCs — `Add.vue` / `Edit.vue` / `View.vue`. The containers never branch on a type; they call `resolveFieldComponent(type, mode)` and mount the result.

> **Full spec** — directory layout, interface contract, `config` merge order, normalization/alias table, precedence, and how to add a type: [`src/_fields/README.md`](file:///f:/LITTLE%20LEAP/AQL/FRONTENT/src/_fields/README.md).

Type-driven presentation layer for every field rendered by `FormRecord.vue`, `ViewRecord.vue`, and `ViewChildCompact.vue`.

Every SFC implements the same surface: `defineModel()` for the value, plus `record: Object`, `config: Object`, `header: String`. All declare `inheritAttrs: false`; `View.vue` components also take `emptyText` (default `'-'`) and `compact` (default `false`, also read from `config.compact`). `compact` is what dense hosts — child tables, line items — pass: `file` collapses to an `attach_file` chip, `status`/`toggle` chips go `size="sm"` with no outer margin, `textarea` becomes one ellipsized line. Types rendering a plain span or inline anchor ignore it.

| Type folder | Add / Edit | View |
|---|---|---|
| `text` (**fallback**) | outlined `q-input` | plain text, null fallback |
| `link` | `q-input type="url"` + link icon/hint | `<a target="_blank">` + `open_in_new` icon |
| `tel` | `q-input type="tel"` + phone icon | `<a href="tel:…">` + phone icon |
| `file` | `AqlFileUpload` | `AqlFilePreviewCard` |
| `textarea` | `q-input type="textarea"` (no `autogrow`/`dense`/`rows` — they collapse it to a text-field look) | multiline text (`white-space: pre-line`) |
| `status` | `StatusToggle`, or `q-select` when `config.options` exists | coloured `QChip` (map overridable via `config.statusColors`) |
| `select` | `q-select` with `use-input` local filtering | resolved option label |
| `date` | `app/Date.vue` | `toLocaleDateString('en-GB', …)` |
| `number` | `q-input type="number"` | `toLocaleString` |
| `currency` | `q-input type="number"` prefixed with the dynamic currency symbol (`useCurrency`) | `_C(value)` |
| `toggle` | `q-toggle` | outlined `QChip` (positive when the stored value is the column's `true-value`) |

| Module | Description | API |
|---|---|---|
| `useFieldResolver` | Eager `import.meta.glob('./*/*.vue')` registry keyed `type → {Add,Edit,View}`. `resolveFieldComponent(type, mode)` maps `add\|edit\|view` → `Add\|Edit\|View.vue`, falling back to `text/<Mode>.vue` for an unknown type or a missing mode file. `normalizeFieldType` collapses schema synonyms (`url→link`, `money→currency`, `dropdown→select`, `boolean→toggle`, …); `resolveFieldType(field)` adds the header heuristics `mapField` uses (`*Date`→`date`, `Status`→`status`) for callers that only hold a raw `UIFields` entry. | `resolveFieldComponent`, `resolveFieldType`, `normalizeFieldType`, `fieldTypes`, `hasFieldType`, `useFieldResolver` — `FRONTENT/src/_fields/useFieldResolver.js` |

**Shared helper** — `resolveDisplayValue(value, emptyText = '-')` in `src/utils/appHelpers.js` produces the default human-readable cell text (relation objects → `Name (Code)` / `Code`, primitives passed through, null → `'-'`). `ViewRecord` and `ViewChildCompact` both feed it into `config.displayValue`, so the detail grid and the compact table never disagree on a cell.

**Precedence is unchanged** — `_fields` is only tier 2: (1) per-resource `_ui` Vue override (`formfield<header>.vue` / `viewcolumn<header>.vue`) → (2) `_fields/<type>/<Mode>.vue` → (3) `_fields/text/<Mode>.vue`. JS modifiers (`FormField<Header>.js`, `ViewColumn<Header>.js`) are not a tier — they merge into `config` and keep working against whichever base type component renders.

| `useListStrategy` | Derives `abstract/List.vue` label/caption/meta/highlight resolvers from a resource's headers, parent relations, and the active list view (`resourceRecord.activeView`). Label: own `Name` → first parent relation with a `Name` column (borrowed, e.g. SKU → Product, with `Variant1..5` appended) → 2+ descriptive columns combined (`"h2 - h3"`) → single descriptive column → `Code`. Caption: multiple parents (`relations.parents.length > 1`) join every parent's name/code with `•`; else a `Date`/`TransactionDate`/`CreatedAt` + `CreatedBy`/`UpdatedBy`/`User`/`Agent` pair; else whatever the label didn't consume. Highlight + meta-chip track `Progress` → `Status` → `Type`; while a list view is active that field is dropped from the chip (redundant with the selected view) in favor of a currency-formatted amount column (`_C` from `useCurrency`) or, for resources with >7 headers, a quantity column — highlight keeps tracking the state column regardless. Data-dense resources (>7 headers) also get a `metaCaption` from an unused descriptive column. Consumed by `contents/List.vue`. | `(resourceConfig, resourceRecord) => { layout, label, caption, metaLayout, chip, chipColor, chipOutline, metaLabel, metaCaption, highlight, highlightColor, clickable }` (all `ComputedRef`) — `FRONTENT/src/composables/resources/useListStrategy.js` |
| `useViewColumnResolver` | Resolves column-level custom UI overrides for fields rendered inside `ViewRecord`. Lookup uses the resource that OWNS the column (`_ui/{ui}/components/{scope}/{resourceSlug}/viewcolumn{col}.(vue\|js)`, then scope-wide, then ui-wide). Exports `resolveColumnOverride({ columnName, resourceSlug, scope, uiName }) => Promise<{ component, modifier }>` for batch resolution, plus the reactive `useViewColumnResolver(...)` composable for single-column use. Supports `.vue` SFC components, `.js` function modifiers, and `.js` object modifiers. | `useViewColumnResolver({ columnName, resourceSlug, scope, uiName }) => { resolvedComponent: ShallowRef, modifier: Ref }` — `FRONTENT/src/composables/resources/useViewColumnResolver.js` |
